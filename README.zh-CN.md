仓盒是一款面向 macOS 的 Subversion 图形客户端。在同一个桌面工作区中管理多个项目，切换工作副本、审阅变更、选择文件提交和查询历史，并保留各个项目的工作上下文。

应用界面支持**简体中文和英文**，可在设置中即时切换。

## 功能

- **多个工作副本** — 按分组整理、搜索、收藏和排序。每个副本独立保留文件选择、筛选条件、展开的目录、历史上下文和提交草稿。
- **远端路径书签** — 集中整理仓库 URL，在紧凑树形列表中展开目录，查看每个目录的加载状态并独立取消，将选中目录检出为独立的本地工作副本。
- **变更审阅** — 紧凑的文件树、SVN 状态筛选，以及文本和属性差异。支持统一或并排显示。
- **选择性提交** — 选择本次提交的路径，审阅实际提交范围，复用近期说明，重启后恢复草稿。
- **历史时间线** — 按日期折叠记录，分页读取历史，查看变更路径，并在单次提交内展开差异。
- **历史内容恢复** — 比较任意两个版本，或历史版本与工作副本；恢复现有文件前自动备份本地内容。
- **文本冲突处理** — 保留更新前的本地内容、采用传入内容，或使用 FileMerge 三方合并；结果需审阅后明确应用。
- **SVN 操作** — 更新、添加、重命名、删除、忽略、撤销本地修改和清理工作副本。查看冲突详情，打开外部比较或合并工具。
- **连接认证** — 在本机加密保存凭据，按连接或仓库路径限定适用范围，让匹配的子路径共用认证。
- **操作日志** — 查看执行状态与命令输出，取消运行中的任务，筛选、复制日志，清空已结束的记录。
- **桌面交互** — 键盘操作、右键菜单、Finder 与终端入口，以及七套外观配色。
- **内置 SVN** — 直接使用随应用提供的 Subversion，也可以在设置中指定本机可执行文件。

## 使用方法

### 添加项目

按 **⌘O** 添加已有工作副本，仓盒会自动识别工作副本根目录及所属仓库。通过侧栏右键菜单修改名称和分组、收藏或调整顺序。移除管理记录只会将其从仓盒中移除。

按 **⌘⇧O** 浏览远端仓库并检出目录。输入 URL，选择本地目标位置和检出深度，需要认证时填写用户名与密码。认证可保存到整个连接，也可以仅用于当前仓库路径。

### 审阅与提交

在侧栏选择工作副本，浏览文件、仅显示变更或按 SVN 状态筛选。选择文件即可查看差异，切换统一与并排视图，也可以在 FileMerge 可用时打开外部比较。

按 **⌘↵** 准备提交，填写说明、选择文件，并在确认前审阅实际提交范围。勾选表示本次提交范围，SVN 没有暂存区。每个工作副本的草稿独立保存。

### 刷新与更新

切回仓盒时会刷新当前副本的本地状态，也可以按 **⌘R** 手动刷新。按 **⌘U** 从仓库更新工作副本，按 **⌘J** 打开操作日志，查看输出或取消运行中的任务。取消不会回滚已经完成的修改。

通过文件右键菜单执行添加、重命名、删除、忽略和撤销本地修改等操作。**撤销本地修改**针对未提交的变更，目录和副本根的操作会包含其后代变更。有数据丢失风险的操作会在确认前展示影响范围。发生冲突时，查看详情，按需使用外部工具处理，刷新状态，再明确标记为已解决。

### 查询历史

切换到历史视图，或在文件、目录的右键菜单中查询指定路径的历史。展开日期和提交查看变更路径，在对应提交内打开差异预览。

搜索框仅筛选已经加载的记录。继续读取更早记录时，会向服务器查询下一页历史。

### 比较与恢复版本

在文件右键菜单选择 **比较 / 恢复版本…**，或从历史记录的行内差异进入。输入两侧仓库修订号，也可以将右侧设为“工作副本”。恢复时，选择起始版本，点击 **恢复此版本内容…**，审阅实际差异并确认覆盖。

恢复支持当前仍存在、大小不超过 32 MiB 的受控普通文件；二进制文件按原始字节恢复，不提供文本预览。仅恢复内容，不改变属性和工作副本基线，也不会自动提交。在“本地备份”中可以审阅并取回覆盖前的内容；备份保存在本机，重启后仍可恢复。

### 处理文本冲突

选择冲突文件，在详情面板保留更新前的完整本地内容、接受完整传入内容，或打开三方合并。FileMerge 会读取基线、本地与传入三个快照，并单独保存结果。保存后回到仓盒，点击 **检查合并结果**，审阅后再应用；关闭外部工具不会标记冲突已解决。

FileMerge 需要安装 Xcode。配置其他工具时，会打开来源与输出文件供手动编辑。文本冲突操作支持 UTF-8 文本；属性、树和二进制冲突需要手动处理。直接编辑工作文件后，应刷新并明确标记解决。

### 调整工作空间

拖动分栏边界调整宽度和高度，或折叠详情面板。按 **⌘,** 打开设置，在**通用设置 → 语言**中切换简体中文或英文，语言与外观立即生效并保存在本机。在**工具**分页配置 SVN 与外部合并工具。重新打开仓盒后，会恢复各工作副本的上下文和提交草稿。

### 更新应用

从 **仓盒 → 检查更新**，或仓库侧栏上方的 **软件更新** 按钮主动检查正式版。发现新版后自动后台下载，按钮原位显示环形进度，可以继续工作；关闭提示不会中断下载，也可以取消后重新检查。更新校验完成后选择 **稍后** 或 **重启以更新**。安装前须先完成正在进行的 SVN 操作，提交草稿会在重启前保存。设置中只保留偏好与版本信息，不再提供更新控件。

更新来自本仓库的 GitHub 正式发布版本，Tauri 更新会验证仓盒独立的签名。Electron 用户切换到 Tauri 版时，需要先手动安装一次。

## Tauri / Rust 开发

这是基于 Electron SVNBox 0.2.1 独立创建的 Tauri 工程，原生迁移参考 Diffolio。保留现有 React 界面，SVN 执行、工作区存储、操作审阅、任务取消、备份、凭据、原生菜单和应用更新均迁移至 Rust。应用使用系统 WebKit，不内置 Electron、Chromium 或 Node.js 运行时；Node.js 仅用于前端开发和构建工具。

环境要求：Apple Silicon、macOS 13.3+、Node.js 26、Rust 1.93+；现有图标需要 Xcode / Icon Composer 27。构建固定版本的 SVN 运行时需要 `scons` 和 `pkgconf`，原生集成测试还需要 Homebrew `subversion`。

```sh
npm ci
npm run dev
```

开发服务仅监听 `127.0.0.1:1421`，正式构建将编译后的前端嵌入应用。

```sh
npm run build
npm test
npm run test:rust
npm run test:native
npm run format:check
npm run check:rust
npm run licenses:check
npm run package:app
npm run package:dmg
```

TS/TSX 沿用 `.prettierrc.json`，Rust 遵循 `src-tauri/rustfmt.toml`，通过 `cargo fmt` 和 Clippy 检查。项目源码统一采用无 BOM 的 UTF-8 编码和 LF 换行；第三方许可证原文保留其原始字节。

### 已有 Electron 数据

首次切换到 Tauri 版时手动安装。首次正常启动会把 Electron 配置中的工作区记录、草稿、操作历史、文件备份和合并会话复制到 `~/Library/Application Support/app.svnbox.desktop`，保留旧配置。已有 Tauri 工作区不会被覆盖。设置 `SVNBOX_DATA_DIR` 可使用独立配置目录，并跳过自动导入。

凭据名称、用户名和作用范围会保留；Electron 加密密码文件作为备份保留，密码需要首次重新输入，随后由 macOS 钥匙串保存，服务名为 `app.svnbox.desktop.credentials`。密码不会写入工作区 JSON，也不通过命令行参数传递。

### 打包与更新

本地打包会在 `src-tauri/target/release/bundle/macos/仓盒.app` 生成临时签名的应用；预览产物位于 `release/preview/<version>/macos/arm64/`。正式发布构建使用 `npm run release:mac`，必须具备 Developer ID 与公证凭据，缺失时会失败，不会降级为临时签名。打包只生成本地产物，发布需要另行执行。

Tauri 更新使用仓盒独立的公钥、签名的 `.app.tar.gz` 更新包和 `latest.json`。签名绑定包内容与声明版本，只接受递增的正式版本；检查由用户主动发起，发现新版后自动后台下载，安装仍需明确确认，存在 SVN 写操作时阻止安装。开发和原生验证构建禁用更新。

迁移机器上的签名私钥单独保存在 `~/.config/svnbox/signing/tauri-updater.key`，不在工程内。其他构建机器可以设置 `TAURI_SIGNING_PRIVATE_KEY` 与 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。后续发布需保留该私钥，不应提交或公开；没有私钥也可以构建不带更新产物的本地应用。

Tauri 更新清单与 Electron 的 `latest-mac.yml` 不兼容，因此 Electron 用户需要手动安装一次 Tauri 版。同一仓库的 `main` 维护 Tauri 版，`electron-legacy` 保留 Electron 版。[迁移说明](docs/migration.md)记录了 Rust 模块分工及验证范围。

### GitHub Actions 发布

仓库沿用 `svn-box/svn-box` 及原有提交历史。发布说明位于 `docs/releases/<version>.md`，npm、Cargo 与 Tauri 的版本号必须一致。

推送与版本号一致的标签（如 `v0.4.0`）会触发 `Release macOS arm64`：在 `xcode-27` 上构建、签名并公证 App 和 DMG，验证解包后的更新包与只读挂载的 DMG，再上传并核验草稿中的文件，最后发布 GitHub Release 与 `latest.json` 更新清单。已有版本不会被覆盖。

日常 CI 仅由 PR 或手动触发；同时推送 `main` 与发布标签时，只执行发布工作流的一轮完整检查。两套流程共用工具链与原生资源准备。发布时仅构建一次正式前端与签名应用，随后用隔离的 debug 测试程序复用该前端做原生回归，正式包不启用测试 feature。用于跨任务传递的正式产物保留 1 天，失败诊断保留 7 天。

工作流使用仓库的 `BUILD_CERTIFICATE_BASE64`、`P12_PASSWORD`、`APPLE_ID`、`APPLE_TEAM_ID`、`APPLE_APP_SPECIFIC_PASSWORD` 和仓盒专用的 `TAURI_SIGNING_PRIVATE_KEY` Secrets。私钥口令如非空，另设 `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`。签名材料仅在构建任务中导入临时钥匙串，结束时清理并恢复原钥匙串搜索列表。
